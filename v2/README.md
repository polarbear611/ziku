# 字库对齐 v2（文字驱动 + 识别打分）

> 多部字帖：用环境变量 `ZIKU_BOOK` 选帖（`v2/books/<帖>/book.json`），默认保母帖。九成宫拓本的处理见 `books/jcg/README.md`。

v1 的做法是「先盲切成格 → 人工写 tokens 配格」，切错一格就会让后面整列错位。v2 换了方向：每页要写哪些字是已知的，程序只需要决定**每个字落在哪一段**。

## 流程

```
work/pages/pNN.png + 释文（v2/text/pNN.tokens 优先，否则 work/tokens/pNN.tokens；只取文字，忽略 - @2 % 这些格标记）
 → align.py   二值化（局部纸色）→ x 投影定列 → 几何 DP（字数 + 宋体字形高度先验）定尺度
 → align3.py  候选切点（墨迹谷底/空白带）→ 每个候选段送 PP-OCRv4 识别模型，读出「该段是字 X」的概率
              → 整页编辑距离式 DP：
                 · 列与列之间的分字由 DP 决定（tokens 的换列位置允许 ±8 字偏差）
                 · 文字里有、图上找不到 → 缺字；图上有、文字里没有 → 废段（校改符号、污渍）
 → refine.py  夹注定位（双行小字不沿列切；优先人工框 v2/text/pNN_notes.json）
 → glyph.py   单字成品图：墨块归属 + 统一字身 + 透明底 PNG（见下）
 → vector.py  potrace 矢量化 -> SVG；预览页 glyph/pNN/index.html（米字格）
 → qa.py      复核分级（⚠️ 目前不在流程里；基于对齐初稿的旧队列已删除，需要时重新运行）
            ：A 疑似错 / B 低置信 / C 无法自动校验（字典外的字、夹注）
 → review.py  生成 review/index.html：只列需要人看的条目，可导出 corrections.json
```

## 单字成品图（glyph.py / vector.py）

| 环节 | 规则 |
|---|---|
| 墨迹归属 | 按连通墨块，不按横线切。主体墨块归所在字；靠近分界的离散部件（黃的八、為的两点、窪的宀、錢的戈钩）用**带约束的单链聚类**：墨块间距离从小到大依次合并，不合并已属于两个不同字的簇——字内部件间距 < 字间距。只有两字真粘连时才按分界切开 |
| 排除 | 字轴外的旁物（校改符号、旁注、邻列笔画）；细长框线碎片；夹注框内的墨 |
| 淡墨 | 滞后阈值：与本字强墨相连的淡墨并入；不相连但整块落在本字框内的淡墨块也并入 |
| 统一规格 | 整页一个字身 S（墨迹长边的 90 分位 / 0.86），墨迹中心对方格中心，**不按单字缩放**，保留原帖字的大小关系；超出方格的才整体缩小 |
| 输出 | `glyph/pNN/NNN.png`（256px RGBA，透明底）、`NNN.svg`（potrace 贝塞尔轮廓，单色填充）、`NNN_src.jpg`（同框原图对照） |

识别模型（PP-OCR）**只用于对齐和复核提示，不用于定字的边界**：它对帖上的异体写法不可靠（如把「窪」认成「崖」、把「硯」认成「視」），曾因此把正确的分界改错。

## 用法

```bash
cd v2
venv/bin/python align3.py p01 p02 …      # -> out3/pNN.json, pNN_extra.json, pNN_ov.jpg
venv/bin/python sheet.py pNN out3        # 逐字拼图，人工抽查用
venv/bin/python refine.py pNN && venv/bin/python glyph.py pNN && venv/bin/python vector.py pNN   # 单字成品图
venv/bin/python qa.py && venv/bin/python review.py   # 复核队列
venv/bin/python ocr_eval.py v1 p02       # 用识别模型给 v1 字库逐页打分（与 v1 的切分无关）
```

v2 用自己的 venv（`rapidocr_onnxruntime`、opencv、opencc、scipy、potracer），不依赖 `work/venv`。potracer 清华源没有，从阿里云源装。

## 已知限制

- 夹注（^）全书约 8 个，不进对齐 DP，用人工框定位（`v2/text/pNN_notes.json`）；没有人工框时自动聚类、标 auto 进复核。
- 全部 18 页已按新流程跑完（`./run_pages.sh`），`build_site.py` 汇总为 `site/`（与线上目录同构）。
- 成品图目检余留问题（离散部件分给邻字，第一版保留）：p02 異41 带上方笔画、皆55 缺上部；p03 門14/寺15、令89/書90；p09 以54 两点归亂55；p10 亦1 缺下部、然131/亦132；p12 鑿71 上部归齒72；p13 八96 撇归字97；p15 作77 并入者78。小校勘点混入：p04 武41 本42、p07 以1 其36 寧48。
- 磨损/缺字不入库：p05 令51 芝52（几乎不可见，`build_site.py` 的 DROP 清单剔除）、p12 九、p14 章、p16 嫌（图上未找到）。
- 淡墨：滞后阈值 + 沿笔画生长 + 按本字墨色归一化 + 描轮廓前平滑；p01 日7 这类极淡笔画仍可能不全。
- tokens 本身的转录问题会表现为缺字/废段，例如 p05 末列「理者與之處」其实在 p06 首列（v1 把 p06 首列整列标成了 `-`），p02「知之之歟」多录了一个「之」。
- 字图边界偶尔带进相邻字的残笔，或在笔画断开处切得不完整（已用宽度先验和 x 向墨团过滤缓解）。
